## Supported boundary

- Disk-backed discovery, exact session metadata, incremental events and bounded waits.
- Durable submission, idempotent reattachment, inspect/wait/cancel and explicit
  uncertain outcomes, without automatic replay.
- Shared sanitized service memory, lifecycle/request diagnostics and health checks.
- Ordinary chat management and messaging through a currently eligible native
  controller, with scoped grants and saved-state/receipt verification. ProDevs is
  covered by prior ordinary-chat unarchive/pin evidence, not only scratch fixtures.
- Existing creation, fork, group and pool workflows retain their documented
  prerequisites and human gates. An exported tool is not unconditional route readiness.

The legacy broker and independent ordinary controller have distinct health.
`driver_status`, `action_health` and `service_health` report eligibility. Native
trust, loader consent, permission raises and destructive confirmations remain
native gates. Bypass does not clear those gates. Unknown sends must be reconciled
using their original request/job identity before any new action.

## Deferred work — excluded from supported release

1. Resident shared-helper keeper integration into production MCP/CLI/UI routing.
   Candidate owner/watchdog binding, exact lock observations and filter auditing
   are retained for later work. No shipped call site imports the keeper.
2. Native receiving settlement, pending-release controller loss, physical-key
   safety, unrelated/concurrent native input and quarantine clearance. The input
   defect remains unresolved; no upstream-only attribution is justified.
3. Unattended cold-app startup, every crash/quit/archive/delete recovery path,
   natural-pressure endurance and automatic native trust/loader/permission gates.
4. Experimental `broker_service_*`, `broker_read_*`, `broker_peer_result_reconcile`
   and `broker_idle` qualification beyond their exact existing enrollments and
   recorded native builds. They remain exposed for controlled engineering use,
   not promoted to generally supported release operations.
5. Cursor authentication/execution, OpenCode execution and fresh loaded-client
   adoption beyond the custom rig. Registrations alone are not execution proof.
6. Broader Codex bridge changes, MCP hot reload and 1Password work remain separate.

`window_manage` and any Tier C fallback remain blocked by the existing UI
quarantine. Native stop-notifier exit zero is not an input-release receipt.
Retained candidate tests and remote read-only helper residency do not clear it.
No new feature work is scheduled by this backlog; resume only on explicit scope.
